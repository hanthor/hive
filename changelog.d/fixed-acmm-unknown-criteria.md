- The ACMM evaluation no longer reports a file as missing when GitHub did not answer. `patternExists` treated every `GetContents` error — rate limit, the 20 s per-repo deadline expiring mid-evaluation, a 5xx — as "absent", so a throttled evaluation showed real files as gaps and **Open All** filed issues for them (tuna-os/tunaOS#2286, #2287, #2298, #2299 asked for `tests/`, `tests/e2e/`, `.github/workflows/` and `codecov.yml` on a repo that had all four). Criteria the evaluation could not decide are now reported as `unknown` (❔ in the panel, "not evaluated", no Open Issue button, excluded from Open All) and counted against the level as not-matched, so an incomplete evaluation can only ever lower a level, never raise it. `criteria_unknown` is reported per evaluation, per repo and per level.
- `POST /api/acmm/issue` refuses (409) to file a gap issue for a criterion the cached evaluation marks as passing or unknown, and reuses an already-open `acmm` issue for the same criterion instead of filing a duplicate — the dashboard only remembered issues it opened during the current page load, so a reload re-filed the same gap. A failure to list existing issues falls through to creation as before.
