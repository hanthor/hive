- `governor.acmm.repo_roots` lets the ACMM evaluation probe a configured subdirectory in addition to the repository root. The codebase criteria are spelled root-relative (`go.mod`, `test/`, `.golangci.yml`, `.github/workflows/`, …), so a repository that keeps its module under `src/` — this one — carried every artifact and self-evaluated at L0 because none of them were found at the top level. With `repo_roots: {hive: src}` each pattern is tried at both `<pattern>` and `src/<pattern>`; present at either passes, undecided at both stays `unknown`, and repositories not listed are probed at the root only as before. The root must be a plain relative path (no leading `/`, `..`, `.` or empty segments, forward slashes only) and anything else fails config validation at load time. See [Repositories whose module lives in a subdirectory](src/docs/acmm-policy-matrix.md#repositories-whose-module-lives-in-a-subdirectory).
